# Data Pipeline Integrity Rules

This rule applies to all files. The data pipeline must stay intact end-to-end.

## Pipeline stages (in order)

```
scripts/run_experiment.sh
  └─ data/raw/exp{N}/{env}/L{level}/run{rep}/
       ├── dagster_runs.csv        # all environments
       ├── pod_timing.csv          # K8s only
       └── metadata.json           # all environments
         ↓
notebooks/analysis.ipynb           ← SINGLE SOURCE OF TRUTH for analysis
  └─ data/processed/*.csv          # aggregated summaries
         ↓
results/*.png                      # generated plots
         ↓
make copy-figures
  └─ docs/figures/*.png            # figures referenced by LaTeX
         ↓
make pdf
  └─ docs/thesis.pdf
```

## `data/raw/` rules

- **Read-only** after experiment runs complete — do not modify CSVs
- Directory structure is **strict** — scripts depend on the exact path pattern
- Required files per run:
  - All envs: `dagster_runs.csv`, `metadata.json`
  - K8s only: `pod_timing.csv`
- `dagster_runs.csv` required columns: `run_id`, `status`, `start_time`, `end_time`, `job_name`, `concurrency_level`, `repetition`
- `pod_timing.csv` required columns: `run_id`, `pod_name`, `submitted_ts`, `scheduled_ts`, `running_ts`, `job_start_ts`
- `metadata.json` required keys: `experiment`, `env`, `level`, `rep`, `timestamp`, `host`

## `notebooks/analysis.ipynb` rules

- **Single source of truth** — all metric calculations live here
- `scripts/analyze_results.py` only invokes this notebook headlessly; never add analysis logic there
- The notebook must be runnable from start to finish with `make analyze` (no manual steps)
- All 12 metrics must be calculated from the raw CSV columns (not hardcoded)
- Export processed summaries to `data/processed/exp{N}_summary.csv` — one row per level

## Propagation rules

When you change something at one stage, you must update all downstream stages:

| Changed | Must also update |
|---------|-----------------|
| A column in `dagster_runs.csv` output | `notebooks/analysis.ipynb` (reader code) |
| Analysis logic in notebook | `docs/chapters/04-results/` (results prose) |
| A metric definition | `docs/chapters/03-method/metrics.tex` FIRST, then notebook, then results chapter |
| A plot output filename | `make copy-figures` target and LaTeX `\includegraphics` references |
| `run_experiment.sh` output path | All `scripts/collect_*.py` and `notebooks/analysis.ipynb` |

## Processed data format (`data/processed/`)

- One summary CSV per experiment per environment: `exp1_vm_summary.csv`, `exp2a_k8s_summary.csv`
- Crossover analysis lives in: `exp3_crossover.csv`
- Column naming: snake_case, lowercase, no spaces
- Never overwrite raw files from the notebook — write only to `data/processed/`

## Results directory (`results/`)

- Only `.png` files — one per metric per experiment
- Naming: `exp{N}_{metric_name}.png`  e.g., `exp1_success_rate.png`, `exp2a_pod_scheduling_latency.png`
- Generated by `make analyze` — never added manually
- Must be regenerated after any change to `notebooks/analysis.ipynb`
